# Configuration

Where every TankLink setting lives, what it defaults to, and how to change it. Build and flash steps are in [`firmware-build-setup.md`](firmware-build-setup.md). Pin wiring is in [`PINMAPS.md`](PINMAPS.md).

## How settings are layered

Each firmware node has two kinds of setting.

**Build options** are compiled into the firmware. They hold pins, timings, and which hardware is enabled. They come from three layers, and the later one wins:

| Layer | File | In git? | Purpose |
| --- | --- | --- | --- |
| 1. Kconfig default | `<node>/main/Kconfig.projbuild` | yes | Fallback and help text for each option |
| 2. Project defaults | `<node>/sdkconfig.defaults` | yes | **The real values for this project.** Change pins here |
| 3. Local config | `<node>/sdkconfig` | **no** (gitignored) | Generated by the build from layers 1 and 2, then edited by `menuconfig` |

**Runtime settings** are changed from the app and saved in the board's flash (NVS). Examples are auto-off time, buzzer, LED brightness, starter type, and float mode. They survive firmware updates. They are cleared by a factory reset or `idf.py erase-flash`.

### Changing a build option

1. Edit `<node>/sdkconfig.defaults`, so the change is committed and every build uses it.
2. Make your local `sdkconfig` pick it up. The build only copies defaults into `sdkconfig` for options it doesn't have yet. **An option already in your local `sdkconfig` keeps its old value.** Do one of these:
   - edit the same line in `<node>/sdkconfig` by hand, or
   - delete `<node>/sdkconfig` and build again, which regenerates it from the defaults, or
   - run `idf.py menuconfig` → **Pump Board** / **TankLink Tank Node**, then copy the value back into `sdkconfig.defaults`.
3. Check the value took effect: `grep PUMP_RTC sdkconfig` (or whichever option you changed).

> `idf.py set-target esp32c3` also deletes `sdkconfig` and regenerates it from the defaults. Anything you set only in `menuconfig` is lost.

A new option added to `Kconfig.projbuild` needs a matching line in `sdkconfig.defaults` too, so its intended value is written down in one place.

## Pump build options (`pump_node`)

Menu: **Pump Board**. The values below are the ones in `sdkconfig.defaults`.

| Option | Value | Notes |
| --- | --- | --- |
| **Status LED** | | |
| `PUMP_ENABLE_NEOPIXEL` | `y` | WS2812 status bar |
| `PUMP_NEOPIXEL_GPIO` | `20` | |
| `PUMP_NEOPIXEL_COUNT` | `11` | LEDs on the bar |
| **Button** | | |
| `PUMP_ENABLE_BUTTON` | `y` | Single button |
| `PUMP_BUTTON_GPIO` | `9` | Parallel with the onboard BOOT button |
| `PUMP_BUTTON_ACTIVE_LOW` | `y` | Button to GND, internal pull-up |
| `PUMP_ACTION_HOLD_MS` | `1000` | Hold then release while off = pump ON |
| `PUMP_PAIRING_HOLD_MS` | `5000` | Hold = BLE pairing window |
| `PUMP_FACTORY_RESET_EXTRA_MS` | `10000` | Keep holding this much longer = factory reset (~15 s total) |
| `PUMP_PAIRING_TIMEOUT_MS` | `60000` | How long the BLE pairing window stays open |
| **Buzzer** | | |
| `PUMP_ENABLE_BUZZER` | `y` | Active buzzer, GPIO HIGH = on |
| `PUMP_BUZZER_GPIO` | `21` | Also UART0 TX, so it may chirp during the ROM boot log |
| **Starter relays** | | |
| `PUMP_RELAY_START_GPIO` | `0` | `-1` = not wired |
| `PUMP_RELAY_STOP_GPIO` | `1` | `-1` = not wired |
| `PUMP_RELAY_ACTIVE_HIGH` | `n` | `n` suits 2-ch opto modules (IN LOW = relay on) |
| `PUMP_RELAY_PULSE_MS` | `400` | Only used until saved settings load. The app's **Starter** setting is the one that counts |
| **DS3231 clock** | | |
| `PUMP_ENABLE_RTC` | `y` | Soft-fails if the chip isn't wired |
| `PUMP_RTC_SDA_GPIO` | `7` | |
| `PUMP_RTC_SCL_GPIO` | `6` | If the chip isn't found, the boot log says whether SDA/SCL look swapped |
| **LoRa (RA-02)** | | |
| `PUMP_ENABLE_LORA` | `y` | |
| `PUMP_LORA_SCK_GPIO` / `MOSI` / `MISO` | `10` / `3` / `2` | |
| `PUMP_LORA_CS_GPIO` / `RST` / `DIO0` | `5` / `4` / `8` | |
| `PUMP_LORA_FREQ_HZ` | `433000000` | **Must match the tank** |
| `PUMP_TANK_PAIR_TIMEOUT_MS` | `60000` | LoRa tank-pair window opened from the app |
| `PUMP_TANK_STALE_SEC` | `1500` | Tank counts as out of range after this long with no packet. **Must match the app** (`tankStaleSec`) |

Other `sdkconfig.defaults` settings: USB Serial/JTAG console, 4 MB flash, the custom `partitions_ota.csv` (two OTA slots), and NimBLE with up to 5 connections and MTU 512.

## Tank build options (`tank_node`)

Menu: **TankLink Tank Node**. The values below are the ones in `sdkconfig.defaults`.

| Option | Value | Notes |
| --- | --- | --- |
| **Sensors and button** | | |
| `TANK_FLOAT_FULL_GPIO` | `4` | Raw level sent. The pump decides what it means |
| `TANK_ENABLE_EMPTY_FLOAT` | `y` | |
| `TANK_FLOAT_EMPTY_GPIO` | `5` | |
| `TANK_BUTTON_GPIO` | `3` | To GND |
| `TANK_LED_GPIO` | `7` | D5. Not GPIO6 (MTCK lights the LED at reset) |
| `TANK_BAT_ADC_GPIO` | `2` | 120 k / 120 k divider |
| **LoRa (RA-02)** | | |
| `TANK_LORA_SCK_GPIO` / `MOSI` / `MISO` | `8` / `10` / `21` | MISO must never be GPIO9. 10 kΩ pull-ups on NSS, SCK, MOSI |
| `TANK_LORA_CS_GPIO` / `RST` / `DIO0` | `20` / `9` / `6` | |
| `TANK_LORA_FREQ_HZ` | `433000000` | **Must match the pump** |
| **Timing** | | |
| `TANK_HEARTBEAT_SEC` | `600` | Deep-sleep wake interval when paired. Keep it well under the pump's `PUMP_TANK_STALE_SEC` (1500) |
| `TANK_TX_RETRIES` | `5` | Send attempts until the pump ACKs |
| `TANK_ACK_TIMEOUT_MS` | `800` | Wait per attempt |
| `TANK_BUTTON_HOLD_MS` | `5000` | Hold = LoRa pairing |
| `TANK_PAIR_WINDOW_MS` | `30000` | How long the tank keeps trying to pair |
| `TANK_BLE_OTA_WINDOW_MS` | `10000` | BLE advertise window after a short press, for OTA |
| `TANK_BUTTON_AWAKE_MS` | `10000` | Stay awake after a short press |
| `TANK_DEMO_NO_SLEEP` | `n` | `y` keeps the tank awake so the USB serial log stays connected. Debugging only: it drains the battery |

Also set: `CONFIG_ESP_SLEEP_GPIO_ENABLE_INTERNAL_RESISTORS=n`, so the float and button pins keep their pull-ups in deep sleep and can wake the chip. Plus the same console, flash, partition, and NimBLE settings as the pump, with 1 connection.

## Runtime settings (set from the app)

Stored on the pump in NVS namespace `pump`, key `cfg`. Defaults apply after a first flash or factory reset.

| Setting | Default | Range / values | App location |
| --- | --- | --- | --- |
| Auto-off | 30 min | 0 (off) – 240 min | Pump settings |
| Buzzer | on for button, pump start/stop, auto-off | per-event switches | Pump settings |
| Buzzer tone | click | click, soft, sharp, double | Pump settings |
| LED brightness | 70 % | 1 – 100 % | Pump settings |
| **Starter type** | **none** | none, two-button | **Starter** |
| Relay pulse | 400 ms | 50 – 2000 ms | Starter |
| Second float | off | off, almost-empty, two tanks | Tank sensor settings |

> **The starter type defaults to "none".** In that mode the pump tracks on/off and the LED, but never pulses the relays. A new or factory-reset pump needs **Starter → two-button** set in the app before it will actually run a motor.

Other data the pump saves (all cleared by factory reset or `erase-flash`):

| NVS namespace | Holds |
| --- | --- |
| `pump` | Runtime settings above |
| `tl_pair` | Phone pairing (paired flag + 16-byte token) |
| `tl_tank` | Bound tank ID, the tank's BLE OTA token, and the last tank packet (`last`) for restoring last-seen after a restart |
| `tl_tanks` | Tank slots and names (two-tank mode) |
| `tl_sched` | Fill schedules (up to 4) |

The tank saves its pairing and BLE OTA token in NVS namespace `tank`.

The pump's **time** is not in NVS. It lives in the DS3231, is set by the phone, and isn't cleared by factory reset.

## Values that must agree across components

| Value | Where | Current |
| --- | --- | --- |
| LoRa frequency | `PUMP_LORA_FREQ_HZ`, `TANK_LORA_FREQ_HZ` | 433 MHz |
| Tank stale window | `PUMP_TANK_STALE_SEC`, app `TankLinkUuids.tankStaleSec` | 1500 s |
| Tank heartbeat vs stale window | `TANK_HEARTBEAT_SEC` must be well below `PUMP_TANK_STALE_SEC` | 600 s vs 1500 s |
| BLE UUIDs, opcodes, payloads | see [`AGENTS.md`](../AGENTS.md#shared-contracts--change-all-copies-together) | — |

## App configuration

| Item | Where |
| --- | --- |
| Version + Android versionCode | `tanklink_app/pubspec.yaml` (`version: X.Y.Z+N`) |
| Android package ID | `com.tanklink.tanklink` (`android/app/build.gradle.kts`) |
| Min Android | API 24 (Android 7.0) |
| Release signing | `android/key.properties` + keystore. Not present today, so builds use the debug key; see [`app-release.md`](app-release.md) |
| Update source | GitHub Releases on this repo (`app-v*`, `pump-v*`, `tank-v*`), highest semver wins |
| BLE UUIDs / opcodes | `lib/ble/tanklink_uuids.dart` |
